# 飞书卡片回答

**Goal:** 群里提出问题后，Codex 把答案放进回复卡片发回原群；继续保留反馈建单和 PR 通知。

**Architecture:** 复用现有群消息接收、Codex 会话和原生 `notice` FYI 回执。增加一个只发送的标准通道 `plugins/feishu-replies/channel.ts`，复用现有机器人配置。中台负责持久队列、送达和重试；AI 决定是否回答及是否建单。

## 本批约定

- 只服务现有单个授权群，群目的地由私有配置决定，AI 不指定地址。
- 回答作为 `notice`，`fyi: true`，正文使用 plain_text。用户在群里继续追问，不增加卡片点击监听。
- 已记录决策不重复建单；当前问题仍可在重派时完成回复。纯问答沿用 `ignored` 表示无需建单，回复内容在中台卡片记录里。
- 创建 Issue 时继续使用已有固定工单回执，避免同一结果再发一张重复卡片。
- 不增加 MCP 工具，不改内核、反馈数据库、PR 插件或自动修代码权限。

## 执行与验证

1. 先写失败测试：原群限制、正文卡片、稳定幂等、已发送不重发、拒绝非 FYI 和其他规则、安装后独立加载、原生 notice 走完整临时中台。
2. 实现只发送通道，修改处理指令以允许直接回答和原生 FYI 回执。同步中英文入口与场景文档。
3. 跑相关测试、原有反馈 44 项、typecheck、format；PR 最终提交三系统 check 与独立审查。
4. 冻结代码安装通道，合并私有配置，空闲时只重启中台。现有 SDK 接收和 AI 服务继续使用原数据。
5. 使用一条真实群提问验证 Codex 回答卡片；不假冒真人、不补答历史消息。读回机器人身份、原群和答案内容。
6. 按仓库约定合并后核对主干和每日检查，不发新版本。
