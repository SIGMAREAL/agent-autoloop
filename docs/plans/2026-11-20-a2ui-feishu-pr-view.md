# A2UI 飞书 PR 视图实施计划

**Goal:** 用官方 A2UI 1.0 表达 PR 查询结果，自行映射飞书卡片，显示标题链接、作者链接、创建及更新时间。

**Architecture:** 现有只读 PR 查询生成真实数据及官方 Basic Catalog 的 A2UI surface；插件包固定依赖官方 @a2ui/web_core 0.15.0，使用 MessageProcessor 与 NodeResolver 校验和解析绑定，再映射飞书 JSON 2.0。界面以私有内容寻址文件保存，原生 notice 只传短引用，不改变中台协议或 4000 字符限制。普通文字回复封装为官方 A2UI Text surface，保留原有纯文本语义。

**Tech Stack:** Node 24+、官方 A2UI 1.0 / Basic Catalog、官方 lark-cli、Node test。

## 本批范围与设计

- 不使用被拒绝的社区飞书渲染器；适配器只实现当前需要的 Column、Row、Text、Divider、Button(openUrl)。不增加表单、交互回调或第二条飞书监听。
- PR 视图独立于数据查询。采用有间距的纵向列表，标题为链接按钮；作者为链接，时间标记创建/更新并显示上海时区；顶部明确仓库覆盖、查询时间、草稿及展示数量。
- 每页最多 8 个 PR、最多 10 页；超出时明确展示上限及仓库 PR 列表入口，不把未展示当不存在。失败仓库必须显式列出。
- native FYI 的正文只携带 a2ui:sha256 引用；加载器只读配置 stateDir/a2ui 下私有、内容哈希匹配的有限大小文件。样式只在组件映射中维护；不允许数据指定收件人、文件路径或可执行行为。
- 新 PR 推送保留已有插件；本批聚焦用户当前询问的 PR 查询视图。

## 实施与验证

1. 先写 PR 元数据和 A2UI 绑定/链接/分页/不完整覆盖/非法引用的失败测试，运行确认失败。
2. 实现 PR 时间字段、A2UI surface 构造、私有文件存储和官方核心驱动的飞书组件映射。
3. 只读查询 MCP 返回可直接用于 notice 的 uiCards，不增加 AI 工具权限；更新处理手册，让 AI 选用视图，不重写真实字段。
4. 运行插件及反馈行为测试、quick/typecheck/format；开 PR 后独立审查，核对最终 head 的三系统 CI。
5. 固定版本安装 UI 包和 wrapper，空闲时仅重启中台；复用真实群问题续办，核对飞书读取和实际画面。未取得画面则如实标记视觉验收未完成。
6. 合并后 main check 与完整 nightly 均通过，更新交付证据，保留长期开发工作树并清理本批临时分支。
